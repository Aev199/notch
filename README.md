# Notch

Портативная «чёлка» в стиле Dynamic Island для Windows 10/11: Rust + Tauri v2 + React.
Один `notch.exe`, без установщика и без прав администратора.

## Что умеет

| Вкладка | Что делает |
|---|---|
| **Полка** | Каждое изображение из буфера (Win+Shift+S, PrtScr, «Копировать изображение») сохраняется как PNG в `cache\shelf` рядом с exe. Сетка в 4 колонки прокручивается колесом. Одинаковые картинки не дублируются: остаётся только самая свежая копия. На полку попадают скриншоты и скопированные картинки, но не превью скопированных объектов: картинка из Word/PowerPoint/Excel несёт с собой готовый PNG/JPEG/GIF, а ячейки, таблицы и объекты AutoCAD — только превью и свои форматы документа. Графические программы (Paint, Paint.NET, Photoshop, GIMP, Ножницы, ShareX…) всегда идут на полку, CAD-программы (AutoCAD, nanoCAD, BricsCAD, Revit…) — никогда; текст из них записывается как обычно. Если картинка всё же не попала, кнопка «+» на полке забирает её из буфера вручную. Хранятся последние 30 скриншотов (настраивается, до 100), старые удаляются. **Группы**: перетащите скриншот на другой (или на группу), чтобы собрать их вместе. Клик открывает группу, кольцо группы не удаляет, «Очистить» их не трогает. Карточку или целую группу можно **вытащить за край чёлки** в мессенджер, браузер или папку (нативный OLE Drag-and-Drop), скопировать обратно или удалить. **Клик** сразу открывает редактор в отдельном окне: кисть, маркер, линия, стрелка (Shift — по 45°), рамка, текст, номера шагов, пикселизация для скрытия данных, обрезка; 6 цветов, толщина ползунком (1–40), размер шрифта 12–100, поворот на 90°, вставка картинки поверх (Ctrl+V из буфера или с полки — двигать и масштабировать инструментом «Выбор»), отмена/повтор, масштаб Ctrl+колесом (пробел + перетаскивание — сдвиг). Окно редактора поверх всех окон; закрытие без вопросов — несохранённые пометки просто отбрасываются. Там же «Текст» — распознать текст встроенным OCR Windows (офлайн; в рамке обрезки, если она есть) и «Перевести». Распознанный текст можно поправить, перевод обновится. «Сохранить» кладёт результат на полку рядом с оригиналом (в ту же группу) и в буфер, оригинал не меняется. |
| **Снимок экрана** | **PrintScreen** замораживает экран (тот монитор, где курсор) и открывает его поверх всего: протяните рамку, поправьте её за края и углы или передвиньте (инструмент «Двигать область», V). Под рамкой — те же инструменты, что в редакторе: кисть, маркер, линия и стрелка (Shift — по 45°), рамка, текст, номер шага, пикселизация; 6 цветов, толщина ползунком, размер шрифта, отмена и повтор (Ctrl+Z / Ctrl+Y), те же клавиши ([ и ] — толщина или шрифт, 1–6 — цвет). Окно появляется сразу, без анимации и без мелькания прошлого снимка. **«Готово»** (Enter, Ctrl+C) кладёт область на полку и в буфер; без рамки Enter берёт весь экран, Ctrl+A выделяет его целиком. **«Текст»** распознаёт текст в области (OCR Windows, офлайн) и кладёт его в буфер, **«Перевести»** сразу открывает перевод. Esc — отмена. Перехват PrintScreen выключается в настройках, если вы пользуетесь другим скриншотером; если клавишу уже занял он, Notch скажет об этом при сохранении настроек. |
| **Файлы** | Перетащите файл или папку на чёлку и подержите треть секунды — она раскроется на вкладке «Файлы»; отпустите. Файлы ждут там, пока вы не вытащите их в другое окно (по одному или «Тащить все»). Запоминаются только пути (до 50), сами файлы остаются на местах; перемещённый или удалённый показан зачёркнутым. Клик открывает файл, кнопка с папкой показывает его в Проводнике. Вкладка выключается в настройках. |
| **Буфер** | Последние 30 скопированных текстов (из Excel/Word/PowerPoint — только скопированное клавишами или через контекстное меню, чтобы «Формат по образцу» не засорял историю). Текст хранится и вставляется в точности как скопирован — с отступами и табуляцией (код, YAML, ячейки таблиц); в списке он показан компактно. Повторы поднимаются наверх, и тексты, которые отличаются только пробелами, считаются одним. Клик по строке возвращает её в буфер и сворачивает чёлку. Кнопка **«Вставить»** сразу вставляет текст в поле, где стоит курсор (Ctrl+V через `SendInput`); та же кнопка есть у перевода и у распознанного текста. **Поиск** по истории (регистр и ё/е не важны; стрелки выбирают строку, Enter вставляет её). **С клавиатуры**: горячая клавиша (по умолчанию `Ctrl+Alt+B`, меняется в настройках) открывает «Буфер» с курсором в поиске — печатайте, выбирайте стрелками, Enter вставит текст туда, где вы работали. **Закреплённые** записи всегда наверху, не вытесняются, не стираются «Очистить» и хранятся в `notch.pins.json`. |
| **Перевод** | RU⇄EN **офлайн**, направление определяется по кириллице. Модели Firefox Translations (Mozilla, движок Bergamot) встроены в exe и работают как WebAssembly, сеть не нужна. По желанию можно включить Google, DeepL или OpenAI-совместимую локальную модель (Ollama, LM Studio). Запуск: **Ctrl+C дважды** в любой программе или горячая клавиша (по умолчанию `Ctrl+Alt+T`): она переводит текст из буфера и ставит каретку в поле ввода. |
| **В проект Papka** | Снимок из окна PrintScreen, скриншот с полки, текст из буфера или файл с полки — кнопкой «В проект…» во «Входящие» проекта файлового менеджера [Papka](https://github.com/Aev199/papka): выбрать проект, подписать, «Отправить». Papka показывает запись в карточке проекта; ей не нужно быть запущенной. Для снимка запоминаются программа и заголовок окна, над которым нажат PrintScreen. Файл не копируется — уходит ссылка на него |

* Наведите курсор на капсулу у верхнего края, и она раскроется сразу; уведите курсор, и она свернётся.
  Всё остальное время окно **пропускает клики насквозь**.
* Через 4 секунды бездействия (настраивается) капсула сжимается в **тонкую полосу** 140×5 у края экрана.
  Полоса не ловит клики: вкладки и заголовки окон под ней работают. Чтобы открыть чёлку, задержите
  курсор у самого верхнего края на 0,15 с. Новый скриншот или текст снова показывает капсулу.
* Поверх полноэкранного окна (F11 в браузере, видео, игры без эксклюзивного режима) чёлка всё время
  остаётся полосой. В эксклюзивном полноэкранном режиме DirectX и в режиме презентации она прячется совсем.
* Окно не забирает фокус у активной программы (`WS_EX_NOACTIVATE`), его нет в Alt+Tab
  (`WS_EX_TOOLWINDOW`) и на панели задач. Фокус берётся только при клике в поле ввода;
  Esc или уход курсора возвращают фокус туда, где он был.
* Содержимое, которое программы помечают как секретное, не записывается: это форматы
  `ExcludeClipboardContentFromMonitorProcessing` и `Clipboard Viewer Ignore` (менеджеры паролей), а также
  `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` со значением 0 (отказ от журнала Win+V и синхронизации).
* На нескольких мониторах чёлка живёт на основном; в настройках можно включить «на том мониторе, где курсор» —
  тогда она переходит вслед за курсором (пока она раскрыта, никуда не прыгает).
* Иконка в трее: открыть, перевести буфер, папка программы, выход.

## Портативность

Всё лежит рядом с `notch.exe`:

```
notch.exe
notch.settings.json     настройки (сервис перевода, ключи, горячая клавиша…)
notch.history.json      история текста — только если включено в настройках (по умолчанию выключено)
notch.pins.json         закреплённые записи буфера
notch.files.json        полка файлов: пути (сами файлы никуда не копируются)
cache\shelf\            скриншоты полки, их миниатюры, groups.json (какой скриншот в какой группе)
                        и hashes.json (отпечатки картинок, чтобы находить повторы, не открывая файлы)
```

Ключи DeepL и локальной модели лежат в `notch.settings.json` открытым текстом: не кладите папку программы
туда, где её читают другие.

Если папка exe недоступна для записи (например, `Program Files`), данные хранятся в `%LOCALAPPDATA%\Notch`
(данные прежних версий из `%TEMP%\Notch` переезжают туда сами).
Автозапуск (переключатель в настройках) прописывает exe в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, права администратора не нужны.

Нужен WebView2 Runtime. В Windows 10/11 он обычно уже установлен вместе с Edge.

## Устройство

```
crates/core/        чистая логика без Tauri, с тестами:
  hover.rs          конечный автомат: полоса / капсула / открыто, сквозной клик, раскрытие под перетаскиваемый файл
  files.rs          полка файлов: список путей, повторы, пропавшие файлы
  papka.rs          «В проект…»: список проектов Papka (projects.json), запись во «Входящие» (формат — docs/INBOX.md в Papka)
  text_history.rs   кольцевой буфер текстов, очистка, дубликаты
  shelf.rs          PNG + миниатюры, кольцо с удалением файлов, группы (индекс groups.json)
  translate.rs      направление RU/EN, запросы и разбор ответов Google/DeepL/LLM
  ocr.rs            подготовка скриншота к OCR (масштаб, BGRA)
  settings.rs       JSON рядом с exe, атомарная запись
  update.rs         выбор выпуска, проверка SHA-256 и подписи, подмена exe с откатом
src-tauri/src/
  overlay.rs        опрос GetCursorPos (16 мс у верхнего края, 50 мс в остальное время), стили окна, полноэкранный режим, позиция, выбор монитора
  capture.rs        снимок экрана по PrintScreen: заморозка монитора (GDI), окно поверх него
  models.rs         встроенные офлайн-модели (models/, gzip)
  ocr.rs            распознавание текста через Windows.Media.Ocr (WinRT)
  clip.rs           слушатель WM_CLIPBOARDUPDATE (clipboard-master), arboard, двойной Ctrl+C
  net.rs            reqwest (SChannel TLS)
  win.rs            Win32: стили окна, фокус, реестр, единственный экземпляр
  state.rs, lib.rs  состояние, команды, трей, горячая клавиша
src/                React + Motion: остров с пружинной анимацией размеров и скруглений, вкладки и настройки
  lib/offline.ts    офлайн-переводчик Bergamot (WebAssembly в воркере), модели берутся из exe по IPC
  capture/          окно снимка экрана (?capture=1): рамка, инструменты, «Текст» и «Перевести»
  editor/           редактор скриншотов (отдельное окно, тот же бандл с ?editor=<id>): модель фигур и отрисовка на canvas
```

Почему сквозной клик устроен именно так: пока окно пропускает клики, страница не получает событий мыши,
поэтому наведение отслеживает Rust. Как только курсор попал на капсулу, окно начинает ловить мышь и
раскрывается. Если курсор пробыл вне острова 350 мс, окно сворачивается и снова пропускает клики.
Пока зажата кнопка мыши, идёт перетаскивание или открыто поле ввода, окно не сворачивается.

Стили `WS_EX_TRANSPARENT | WS_EX_LAYERED` (сквозной клик) и `WS_EX_TOOLWINDOW` выставляет только поток
наведения, на каждом такте. Tauri переписывает расширенные стили целиком, когда меняет что-то своё
(например, `focusable` для `WS_EX_NOACTIVATE`). Такой сбой исправляется на следующем такте, а гонки
двух потоков за один стиль больше нет: раньше из-за неё кнопки иногда не нажимались.

## Обновления

Схема та же, что в Papka:

- Раз в сутки (и по кнопке «Проверить» в настройках) Notch смотрит выпуски GitHub; `notch.exe`
  сверяется с SHA-256 из `latest.json`.
- Если программе закрыт интернет, «Скачать в браузере» открывает
  `releases/latest/download/notch.exe` в браузере, а Notch 20 минут следит за «Загрузками»
  (и проверяет их раз в час): найденный `notch.exe` (или `notch (1).exe` — так браузеры называют
  повторные загрузки) новее текущего предлагается установить. Файл должен называться именно так, а в его
  свойствах должно стоять название программы «Notch»; версия читается оттуда же. Чужие программы с
  похожим именем не подходят.
- Установка: работающий `notch.exe` переименовывается в `notch.old.exe`, новый встаёт на его место,
  при ошибке всё возвращается. «Перезапустить» запускает новую версию; «Вернуть предыдущую» меняет
  файлы местами.
- Версия = `0.1.<номер сборки>`; локальные сборки (`0.1.0`) сами не проверяют обновления.

### Подпись выпусков

SHA-256 из `latest.json` ловит повреждённую загрузку, но лежит в том же выпуске, что и exe: тот, кто
может подменить выпуск, подменит и его. От этого защищает подпись Ed25519 — она выключена, пока в
программу не вписан ключ. Чтобы включить:

```
openssl genpkey -algorithm ed25519 -out notch-signing.pem
openssl pkey -in notch-signing.pem -pubout -outform DER | tail -c 32 | od -An -tx1 | tr -d ' \n'
```

1. Содержимое `notch-signing.pem` положите в секрет репозитория `NOTCH_SIGNING_KEY`
   (Settings → Secrets and variables → Actions) и сохраните файл в надёжном месте вне репозитория.
2. 64 шестнадцатеричных знака из второй команды впишите в `PUBLIC_KEY` в `crates/core/src/update.rs`.

После этого workflow прикладывает к выпуску `latest.json.sig`, а программа с вписанным ключом принимает
из сети только подписанные выпуски. Уже установленные версии без ключа продолжают обновляться как
раньше, поэтому переход не требует ручных действий. Обновление через «Загрузки» подписью не покрыто:
там файл скачивает браузер с github.com, и проверяются только имя и свойства файла.

## Сборка

Windows, Rust stable, Node 22:

```
npm ci
npx tauri build
```

Готовый файл: `src-tauri/target/release/notch.exe` (около 55 МБ, почти всё занимают модели перевода). Его же собирает GitHub Actions
(`.github/workflows/windows.yml`, артефакт `notch-portable-N`, хранится 7 дней). Чтобы выпустить релиз,
запустите workflow вручную с `release: true`.

Проверки из Linux:

```
cargo test --manifest-path crates/core/Cargo.toml
cargo clippy --manifest-path crates/core/Cargo.toml --all-targets
npm test
npm run build
cd src-tauri && cargo check --target x86_64-pc-windows-gnu   # нужен mingw-w64
```

## Происхождение

Основа взята из [PILLAR](https://github.com/WarPirate/pillar-dynamic-island-for-windows) (MIT):
прозрачная сцена поверх всех окон, позиционирование у верхнего края, пружинная анимация на Motion.
Модули PILLAR (системный монитор, медиаплеер, громкость, уведомления, ИИ-чат Prism) убраны,
каркас переписан под три вкладки. Перетаскивание наружу сделано на
[tauri-plugin-drag](https://github.com/crabnebula-dev/tauri-plugin-drag) от CrabNebula.
Офлайн-перевод сделан на [bergamot-translator](https://github.com/browsermt/bergamot-translator)
(MPL-2.0) с моделями Firefox Translations от Mozilla (MPL-2.0); откуда взяты модели и их контрольные
суммы, описано в `src-tauri/models/README.md`.
